## The Fraud Test Agent (fraud.webmesh.ai, v1.0.3)

An adversarial **attack battery** — the server-side twin of our `cmd/battery`. It
runs against a **Supplier** and expects every attack **BLOCKED**; `VULNERABLE` or
`INCONCLUSIVE` is a supplier defect. Tools (MCP, streamable-http):

`run_battery`, `replay_booking`, `underpay_booking`, `tamper_mandate`,
`underpay_valid_sig`, `quote_swap_attack`, `wrong_audience_attack`,
`wrong_scope_attack`, `wrong_dpop_key_attack`, `corrupt_jws_attack`,
`superseded_format_attack`, `unknown_key_mandate`, `replay_settled`,
`canonicalization_probe`, `payto_binding_check`, `card_drift_watch`.

These names are **1:1 with our battery** (internal/battery). Expected rejection
codes the fraud agent looks for: `MANDATE_REJECTED`, `DPOP_REJECTED`,
`MANDATE_PARSE_ERROR`, and for `replay_settled` one of `MANDATE_REJECTED` /
`PAYMENT_REQUIRED` / `EVM_SETTLEMENT_FAILED`.

## The Supplier contract (supplier.webmesh.ai, v1.0.4)

The thing the fraud agent attacks. Two MCP tools:

### `get_quote` (x402-gated, read-only)
```
inputSchema: { origin: string(IATA), destination: string(IATA),
               date: string(YYYY-MM-DD), party_size: int=1 }   required: origin,destination,date
```
Returns three deterministic flight options. "x402-gated: caller pays a small
test-USDC fee for each quote request."

### `book_flight`
```
inputSchema: { quote_id: string, option_id: string, mandate: string,
               dpop_proof: string, payment_auth: string="" }   required: quote_id,option_id,mandate,dpop_proof
```
Verification order (from the tool description):
1. mandate `quote_id` == booking's `quote_id` (quote binding)
2. mandate signature (**RFC 9421 AP2, Ed25519, signed by the Spending Authority**)
3. mandate audience == supplier's ANS name
4. mandate scope route+date matches supplier inventory
5. mandate `max_amount` >= option price
6. mandate time window valid
7. DPoP proof generated by the `jkt` key for this exact request
8. **EIP-3009 on-chain settlement on Base Sepolia** (when `GOVWARE_EVM_ENABLED=1`,
   atomic with the ticket) — "No ticket without on-chain settlement."

Identity: Ed25519 trust card with a GoDaddy Private ANS x5c chain; ANS names
`ans://v1.0.4.supplier.webmesh.ai` etc.; noAuth transport (security is the mandate
+ DPoP + payment, not TLS client auth).

## The two gaps (why this needs a decision)

1. **On-chain payment (item 2c).** The supplier's *happy-path* `book_flight`
   requires an EIP-3009 `transferWithAuthorization` submitted on Base Sepolia
   before it issues a ticket. **We do not implement on-chain settlement** (an
   Honest Limit). *But* the fraud agent only ever sends **invalid** requests — all
   13 attacks/probes are rejected at steps 1–7, **before** the payment step. So a
   correct supplier passes the battery **without** doing any on-chain payment; the
   payment step is only reached by a fully valid booking, which the battery never
   sends. Our adapter would reject a fully valid booking with `PAYMENT_REQUIRED`
   (documented honest limit) and still block all 13 attacks.

2. **Mandate wire format.** The supplier's mandate is **AP2 / RFC 9421, Ed25519**
   ("purchase:flight:*" scope, `max_amount`, `quote_id`, flight route/date). Our
   mandate is `overpass-mandate+jws`, **ES256**, scope `pass:<mode>:<norad>`,
   `max_amount_cents`. The *properties* each attack tests (signature integrity,
   audience, scope, amount, quote binding, DPoP replay/key, canonicalization,
   payTo attestation, card drift) are **exactly what our chain already enforces**
   (phase 7: 23/23 blocked) — but on a **different wire format**. So the adapter is
   not a thin call-reshape onto `book_pass`; it needs an **AP2 mandate verification
   path** (parse the AP2 mandate, verify its Ed25519 signature against the expected
   authority key, check audience/scope/amount/quote/window/DPoP, track a replay
   nonce), returning our named codes.

## Proposed check → our check → code → test (to build in item 2b/2d, NOT yet built)

| Fraud attack | What it sends | Our rejection point | Code |
| --- | --- | --- | --- |
| tamper_mandate / underpay_booking | signed mandate mutated after signing | AP2 signature verify fails | `MANDATE_REJECTED` |
| corrupt_jws_attack | flipped signature bytes | AP2 signature verify fails | `MANDATE_REJECTED` |
| unknown_key_mandate | signed by a key not in the authority trust card | key not trusted | `MANDATE_REJECTED` |

| wrong_scope_attack | scope route mismatch | scope check | `MANDATE_REJECTED` |
| replay_booking | replayed DPoP proof | DPoP nonce replay cache | `DPOP_REJECTED` |
| wrong_dpop_key_attack | DPoP from a key != mandate.jkt | DPoP key binding | `DPOP_REJECTED` |
